## 🚨 这个版本修了什么

### 现象

应用放在后台时，**到点了收不到通知**；一打开应用，通知才弹出来。

### 根因（完整链条）

1. **缺少 `USE_EXACT_ALARM` 权限** —— 应用只声明了 `SCHEDULE_EXACT_ALARM`，
   而后者在 Android 12+ 需要用户手动去系统设置里开。
2. 没这个权限时，`setAlarmClock()` **会抛异常**，代码就悄悄退回了非精确闹钟 `set()`。
3. **非精确闹钟会被系统批处理延迟** —— 应用在后台甚至要等进程被「解冻」
   （也就是用户手动打开应用）才发出来。

实测记录（模拟器 Android 16，应用在后台被系统冻结）：

| | 修复前 | 修复后 |
| --- | --- | --- |
| 实际使用的闹钟类型 | `inexact`（非精确） | `alarmclock` |
| 预定 23:04:26 | 实际 **23:05:08**（晚 42 秒） | 实际 **23:04:26.167**（准点） |
| 通知发出时刻 | 应用解冻后才发 | **23:04:26.175**（闹钟后 8 毫秒） |
| 当时应用状态 | 已被手动打开 | **仍在后台冻结中** |

### 修法

**声明 `USE_EXACT_ALARM`**（Android 13+）—— 这个权限**安装即自动授予，用户不需要做任何操作**。

它的官方定位是给「闹钟 / 日历类应用」用的，本应用的核心功能就是定时提醒，符合定位；
而且本项目走 GitHub 直接分发、不上架 Google Play，不受 Play 的权限政策限制。
`SCHEDULE_EXACT_ALARM` 保留作为 Android 12 的兜底。

### 附带改进

- **自检页新增「上一次闹钟」诊断行**：显示上次闹钟**实际响的时刻**和**用的哪种闹钟**。
  这条是专门为了区分下面两种情况加的：
  - 有触发记录却没看到通知 → 系统把通知压住了
  - 没有触发记录 → 闹钟压根没响，问题在后台策略
- **降级时会记录原因**：万一将来又退回非精确闹钟，自检页会直接把失败原因显示出来，
  不再默默降级。
- 「精确闹钟」那一项的警告文案改准确了：之前写「可能晚几分钟到几十分钟」，
  实际更严重 —— **应用在后台时可能一直不发**。

## ⚠️ 升级说明

- **直接覆盖安装即可**，数据不会丢
- 升级后到 **设置 → 提醒 → 通知自检与修复**，「精确闹钟」一项应该自动变成 ✓
- 然后点一次「1 分钟后发一条通知」，**把应用切到后台**，等一分钟 ——
  这次通知应该会自己弹出来

这个 bug 是用户在实际使用中发现的，而且描述得非常精确：

> 应用放在后台，始终无法收到通知……时间到了后，我返回应用界面，通知才会弹出
