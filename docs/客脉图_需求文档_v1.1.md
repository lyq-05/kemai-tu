## 1. 项目概述

### 1.1 一句话定位

**一款运行在安卓手机上的「客户关系思维导图 + 拜访清单」**：把每一位客户当作导图上的一个节点，按"谁介绍了谁"的层级自动铺开成一张无限延展的图；同时按办卡时间自动生成拜访任务，提醒你维护好每一位客户。

### 1.2 背景与目标

- **使用范围**：你本人及朋友自用，不上架应用商店、不面向公众发布。
- **要解决的问题**：客户信息散落在微信备注、备忘录、纸笔里 —— 既看不清"客户从哪来、谁介绍了谁"，也容易忘记"哪位新客户该去拜访了"。
- **达成效果**：
  1. 打开应用就是一张图，介绍脉络一目了然；
  2. 新客户自动进入每周拜访清单，不会漏跟；
  3. 每位客户的拜访历史可追溯，下次拜访前能翻上次聊了什么。

### 1.3 典型使用场景

| # | 场景 | 用户动作 |
| --- | --- | --- |
| 1 | 老客户 A 介绍来 B、C | 在 A 节点下加两个"下级" |
| 2 | B 又介绍来 D | 在 B 节点下加"下级" D |
| 3 | 客户办了卡 | 点开节点 → 选首次办卡日期 → 勾选产品 |
| 4 | 想补记客户的其他信息 | 编辑面板里加"自定义条目"，如 `微信号 / 同手机号` |
| 5 | **新客户该拜访了** | 顶部清单入口有红点 → 进清单看到本周名单 → 拜访后打勾并记录内容 |
| 6 | 客户多到看不完 | 折叠不常看的子树，或搜索名字直接飞过去 |
| 7 | 换手机 / 重装 | 导出备份文件 → 新机导入恢复 |

### 1.4 分期交付计划

| 阶段 | 版本 | 包含内容 | 交付顺序 |
| --- | --- | --- | --- |
| **阶段一** | **核心版 v1.0** | 无限导图画布、客户字段（名称/办卡时间/产品/备注/自定义条目）、介绍关系、产品库、搜索、折叠子树、设置（主题/字号）、本地存储、备份导出导入 | **先做** |

> 两阶段共用同一套数据结构与代码基础，提醒版是**增量叠加**，不会推翻核心版。核心版的数据在升级到提醒版后完整保留。

| # | 素材 | 用途 | 推荐规格 | 格式 | 备注 |

**给你的设计建议（避免返工）**：

- 主色请沿用**青瓷蓝绿系**（见 8.2），因为导图节点会用到 6 种色相区分不同客户家族，图标/背景如果也用高饱和色，会和节点"打架"。
- 背景素材**越安静越好**。无限画布上会飘着几十上百个彩色卡片，背景再有花纹就糊了。建议：极淡的纸纹/云纹/渐变，或干脆只做四角装饰。
- 边框修饰物建议做成**可拉伸**的（九宫格），因为顶部栏在不同机型上宽度不同。

## 4. 核心数据结构

### 4.1 对象总览

```
客户 Customer ──(介绍关系)──> 客户 Customer        ← 导图的树形骨架
      │
      ├──(多选)──> 产品 Product                    ← 来自可维护的产品库
      ├──(多条)──> 自定义条目 CustomEntry          ← 标签 + 内容
      └──(多条)──> 拜访记录 VisitRecord            ← 每次拜访的历史

拜访清单 VisitList ──(多条)──> 清单项 VisitItem ──(可关联)──> 客户
       ▲
       └── 一张系统自动生成（新客户每周拜访），其余由你自建

设置 Settings                                      ← 主题、字号、提醒规则
```

### 4.2 客户字段（定稿）

| # | 字段 | 类型 | 必填 | 输入方式 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 1 | **客户名称** | 单行文本 | ✅ | 键盘 | 导图节点上显示的文字，最长 20 字，超出省略 |
| 2 | **首次办卡时间** | 日期 | ⬜ | 日期选择器 | 精确到「日」；未填则节点无标记，且不进自动拜访清单 |
| 3 | **使用过的产品** | 多选标签 | ⬜ | 产品库多选 | 可多选；支持边输边搜，搜不到即新建 |
| 4 | **备注** | 多行文本 | ⬜ | 键盘 | 随手写的长文本，最长 2000 字，不用起标签 |
| 5 | **自定义条目** | 多条「标签 + 内容」 | ⬜ | 见 4.3 | 条数不设上限，解决"想填却没地方填" |
| — | *介绍人* | 引用客户 | ⬜ | 选择器 | **非普通字段**，决定节点在导图中的位置，见 4.4 |

### 4.3 自定义条目（CustomEntry）

这是你特别要求的「防止有客户信息想添加，却没有留有空间填写」的落地方式。

| 项目 | 设计 |
| --- | --- |
| 结构 | 每条 = **标签**（短文本，最长 12 字）+ **内容**（文本，最长 500 字） |
| 数量 | **不设硬上限**（实际录入通常 0–10 条） |
| 操作 | 随时新增、删除、上下拖动排序 |
| **标签自动记忆** | 输入标签时，从**你历史上用过的所有标签**中自动补全（输"微"就能选出"微信号"）—— 既保证每张卡都能自由加，又能自然沉淀出你自己的常用字段 |
| 快捷新增 | 补全列表顶部提供你**最常用的 3 个标签**，一键填入 |
| 显示位置 | 编辑面板下半部分；客户卡片上**不显示**（保持画布整洁，Q7 已定） |

> 举例：`微信号 / 同手机号`、`生日 / 3月18日`、`家庭情况 / 孩子上小学，有转介绍机会`、`注意事项 / 周一上午不要打电话`。

### 4.4 介绍关系规则

| 规则 | 内容 |
| --- | --- |
| 介绍人数量 | 一个客户**最多一个**介绍人（上级） |
| 下级数量 | 一个客户可有**任意多个**下级 |
| 根节点 | 无介绍人的客户即"根客户"，**允许多个根** |
| 同级 | 拥有**同一介绍人**的客户互为同级 |
| 禁止成环 | 不允许 A 介绍 B、B 又（间接）介绍回 A，实时校验拦截 |
| 深度 / 广度 | **均不设上限** |

### 4.5 拜访清单数据结构（阶段二）

| 对象 | 字段 |
| --- | --- |
| **清单 VisitList** | id、名称、类型（`系统·新客户每周拜访` / `自建`）、排序、创建时间、手动移出名单、手动加入名单 |
| **清单项 VisitItem** | id、所属清单、客户名称、关联客户 id（可空）、**计划回访时间**（可空）、**回访内容**（可空）、是否已完成、**实际完成日期**（可空）、排序 |
| **拜访记录 VisitRecord** | id、客户 id（可空）、客户名称快照、清单项 id、计划回访时间、实际完成日期、回访内容 |

- 「清单项」是**当前待办**；「拜访记录」是**完成后留下的历史**，客户详情里可查。
- 客户名称：**优先从导图已有客户中选**（选中后可一键跳转到该节点），**也允许直接手输**不在导图里的名字（此时关联客户 id 为空）。

### 4.7 规模与上限（回应你的关切）

**不设任何数量上限。** 架构按"无上限"设计：

| 措施 | 作用 |
| --- | --- |
| 视口裁剪渲染 | 只绘制屏幕可见区域内的节点与连线，画布再大也不影响帧率 |
| 布局计算后台化 | 结构变化时在后台线程增量重算，不阻塞 UI |
| 折叠 / 展开子树 | 把不常看的整棵子树收成一个点，画布信息密度由你掌控 |
| 搜索定位 | 无论多少客户，输入名字直接飞过去并高亮 |

> **务实提醒**：客户到 300 位以上时，真正的瓶颈不是性能而是"看不完"。所以「折叠子树」和「搜索」我在 v1.1 里**都纳入了核心版**，这是"客户变多之后仍然好用"的关键。若你希望核心版更小，可以砍掉折叠子树（见第 13 章）。

## 5. 核心界面设计

### 5.1 主界面：无限导图画布

#### 5.1.1 布局规则（依据你的确认）

```
                     ┌─────────┐
                     │  客户A  │          ← 根客户（无介绍人）
                     └────┬────┘
              ┌───────────┴───────────┐
              │                       │
         ┌────┴────┐             ┌────┴────┐
         │  客户B  │             │  客户C  │   ← B、C 同级（横向并排）
         └────┬────┘             └─────────┘
              │
         ┌────┴────┐
         │  客户D  │                        ← B 的下级
         └─────────┘
```

| 方向 | 含义 | 效果 |
| --- | --- | --- |
| **竖向（向下）** | 层级变深 | 下级永远排在上级**下方**，形成代际 |
| **横向（左右）** | 同级并列 | 兄弟节点从左到右依次排开，互不遮挡 |
| 自动对齐 | — | 父节点**水平居中**于其所有子节点之上 |
| 无限延展 | — | 深度与宽度均不设上限，画布随之无限扩展 |

#### 5.1.2 多个根客户

多个互不相关的根客户**从左到右横向并排**，各自带一整棵子树，子树之间留更大间距以示分隔：

```
   ┌─────────┐        ┌─────────┐        ┌─────────┐
   │  客户A  │        │  客户X  │        │  客户M  │
   └────┬────┘        └────┬────┘        └─────────┘
   ┌────┴────┐             │
┌──┴──┐   ┌──┴──┐     ┌────┴────┐
│客户B│   │客户C│     │  客户Y  │
└─────┘   └─────┘     └─────────┘
```

#### 5.1.3 折叠 / 展开子树

| 项目 | 设计 |
| --- | --- |
| 入口 | 有下级的节点，卡片右下方有一个小圆形折叠按钮（`−` / `+`） |

## 7. 提醒机制设计（阶段二）

### 7.1 三层结构（你已确认"三层全做"）

| 层级 | 做法 | 可靠性 | 依赖 |
| --- | --- | --- | --- |
| ① **入口 + 角标** | 顶部栏"拜访清单"入口，红色角标显示未拜访数量 | 完全可靠 | 无 |
| ② **应用内横幅** | 打开应用时，画布顶部一条可关闭提示条："本周有 5 位新客户待拜访 · 查看" | 完全可靠 | 无 |
| ③ **系统通知** | 按设定时间发一条**汇总**通知，点击直达清单页 | 可能被厂商省电策略拦截 | 通知权限 |

**不做"闹钟"**：写系统日历/闹钟需要额外权限、会在你的日历里留下垃圾条目、体验割裂。

**关于 ③ 的诚实说明**：小米 / 华为 / OPPO / vivo 对后台任务管控很严，系统通知**有可能延迟甚至不送达**。因此它的定位是"锦上添花"，**①② 才是可靠底线** —— 只要你打开应用，就一定看得到，不会漏跟。

### 7.2 自动清单「新客户每周拜访」规则

| 项目 | 规则 |
| --- | --- |
| 入列条件 | 首次办卡时间在**最近 N 个月**内（N 默认 6，可改 3 / 6 / 12） |
| 未填办卡时间 | **不进入**自动清单（无法判断） |
| 周期 | 每周一 00:00 重置"本周已拜访"状态 |
| 排序 | 按办卡时间由新到旧；已拜访的置灰沉底 |
| 手动干预 | ✅ 允许**移出/暂停**个别客户（出差、客户明确说别来等）；✅ 允许**手动把人加进来**（即使不符合条件） |
| 显示 | 每位客户显示：名称、办卡日期、计划回访时间（未填显示 `—`）、完成勾选框 |

### 7.3 通知调度实现

| 项目 | 方案 |
| --- | --- |
| 技术选型 | 系统自带 `AlarmManager` + `androidx.core` 通知 —— **零第三方依赖、零网络** |
| 调度方式 | 一次性闹钟触发后自行续订下一次；应用每次打开时校正一次（防止被系统清理） |
| 重启恢复 | 监听 `BOOT_COMPLETED` 重新排定 |
| 通知内容 | 标题「客脉图 · 拜访提醒」，正文「本周有 5 位新客户待拜访」，点击直达清单页 |
| 精确性 | 使用**非精确闹钟**，无需"精确闹钟"权限；实际送达时间可能有几分钟到数十分钟偏差（对周提醒完全可接受） |
| 通知渠道 | 独立渠道「拜访提醒」，你可在系统设置里单独调节 |

### 7.5 通知可靠性自检与引导（★ 你特别要求）

**背景**：你实际遇到过 VIVO 的"智能控制后台耗电"**偶发拦截通知**，把该应用改为"允许后台高耗电"后解决。这类问题**绝不能让你去猜"通知为什么没响"**。

**做法**：设置 → 提醒 → 点击 **「通知是否正常？」**，进入自检页：

| 检查项 | 显示 | 不合格时 |
| --- | --- | --- |
| 通知权限 | ✅ 已开启 / ❌ 未开启 | 提供 [ 去开启 ] 直达系统设置 |
| 电池优化 | ✅ 已忽略优化 / ⚠️ 系统可能限制后台 | 提供 [ 去设置 ] |
| 后台运行限制 | ✅ 未受限 / ⚠️ 可能被限制 | 提供 [ 去设置 ] |
| 厂商后台策略 | ⚠️ 需你手动确认（无法自动读取） | 按**你的机型品牌自动匹配**图文步骤 |
| 下次提醒时间 | 2026-10-06 09:00 | — |

底部一个 **[ 发一条测试通知 ]** 按钮，立即验证通道是否畅通 —— 不用等到下周一才知道有没有生效。

**内置厂商引导（按机型品牌自动匹配）**：

| 品牌 | 设置路径 |
| --- | --- |
| **VIVO / iQOO** | 设置 → 电池 → 后台耗电管理 → 客脉图 → **允许后台高耗电** |
| 小米 / Redmi | 设置 → 应用设置 → 客脉图 → 省电策略 → **无限制**；并开启**自启动** |
| 华为 / 荣耀 | 设置 → 应用 → 应用启动管理 → 客脉图 → 关闭"自动管理" → 勾选**允许自启动 / 关联启动 / 后台活动** |
| OPPO / 一加 / realme | 设置 → 电池 → 应用耗电管理 → 客脉图 → 允许**后台运行** + **自动启动** |
| 三星 | 设置 → 电池 → 后台使用限制 → 把客脉图从"休眠应用"中移除 |

**并在提醒设置页顶部常驻一行说明**（不让你猜）：

> ℹ️ 系统通知可能受手机省电策略影响而延迟或不出现。**顶部「拜访清单」入口的角标永远是准的** —— 打开应用即可看到本周名单，不会漏跟。

这样即使通知没响，你也**立刻知道**：① 该去哪儿看；② 为什么没响；③ 怎么修。

## 8. 视觉与设计规范

### 8.1 设计原则

**工整、克制、耐看**。无限画布最怕杂乱，因此：靠色相区分客户家族、靠圆角折线保证连线利落、靠统一间距网格保证呼吸感。

### 8.2 配色

**主色：青瓷蓝绿 —— 这是「强调色」，不是背景色**

用于：按钮、选中态、开关、输入框聚焦、图标高亮、角标。

**画布背景保持中性（暖白 / 近黑）**，理由：

1. 导图要用 **6 种子树色相**区分不同客户家族，**只有叠在近中性底上才分得清**；背景本身若带青绿，节点颜色会糊成一片；
2. 你后续要替换**全局背景图**，中性底最容易搭配，也不会和你的素材冲突；
3. 青瓷本身温润不冷硬（中国传统色），配"客户往来"的人情味；明度适中，在浅底上做文字/图标对比度足够；与 6 个子树色相都能拉开距离，不抢戏。

| 用途 | 浅色模式 | 深色模式 |
| --- | --- | --- |
| 主色（强调） | `#2F6E6A` | `#7FC9C2` |
| 画布背景 | `#FBFAF7`（暖白） | `#14181A` |
| 网格点 | `#00000014` | `#FFFFFF12` |
| 卡片底色 | `#FFFFFF` | `#1E2426` |
| 主文字 | `#1C2321` | `#E8EDEB` |
| 次文字 | `#6B7674` | `#93A09D` |
| 分隔线 | `#E6E4DF` | `#2C3436` |

**子树色相轮换**（同子树同色相，根最深、逐层变浅）

| # | 色相 | 浅色模式基色 | 深色模式基色 |
| --- | --- | --- | --- |
| 1 | 青瓷 | `#2F6E6A` | `#7FC9C2` |
| 2 | 靛蓝 | `#3A5FA8` | `#8FAEE8` |
| 3 | 松绿 | `#4A7C3F` | `#9BC98F` |
| 4 | 赭石 | `#A8573A` | `#E0A188` |
| 5 | 藤紫 | `#6B4F8A` | `#B79ED6` |
| 6 | 藏青 | `#2C4A6E` | `#8BA8C9` |

> 第 7 位根客户起，色相循环复用。

### 8.3 字号档位（你已确认：全局字号，4 档）

| 档位 | 缩放 | 客户名称 | 面板标题 | 正文 / 标签 | 适用 |
| --- | --- | --- | --- | --- | --- |
| 小 | 0.85× | 14sp | 17sp | 12sp | 想在一屏看到更多客户 |
| **标准** | **1.00×** | **16sp** | **20sp** | **14sp** | 默认 |
| 大 | 1.15× | 18sp | 23sp | 16sp | 日常偏舒适 |
| 特大 | 1.30× | 21sp | 26sp | 18sp | 视力不便时 |

- 全局生效（导图、面板、设置页统一缩放），图标尺寸不随之改变。
- 字号变化后导图**自动重新布局**（卡片变宽，间距与居中关系随之重算），保持工整。
