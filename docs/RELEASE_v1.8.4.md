## 🚨 这个版本改了什么

### 背景：一次关键的用户对照实验

用户在 iQOO Neo9S Pro+（OriginOS 4 / Android 14）上做了逐项对比：

| 设置项 | 个人工作台（通知正常） | 客脉图（被延迟 3 分钟） |
| --- | --- | --- |
| 自启动 | 关 | 关 |
| 后台耗电管理 | 允许后台高耗电 | 允许后台高耗电 |
| 悬浮通知 / 锁屏通知 | 开 | 开 |
| 关联启动 | 关 | 关 |

**系统设置完全一致，但一个稳定成功、一个稳定失败。**
这说明差别不在系统设置，而在**应用自己**。

再结合客脉图自检页当时的数据：

```
本次排定    闹钟式（最强闹钟类型）
精确闹钟    ✓ 已授权
电池优化    ✓ 已加入白名单
上一次闹钟  预定 00:47 → 实际 00:50（晚 3 分钟）
```

**应用侧三项全部就位，仍然被延迟。**

### 找到的差异

| | 个人工作台 | 客脉图（v1.8.0~v1.8.3） |
| --- | --- | --- |
| 精确闹钟权限怎么来的 | 用户**手动**去系统「闹钟与提醒」打开的 | `USE_EXACT_ALARM`，**安装时自动授予** |
| 用户有没有去过那个页面 | 有（应用主动引导） | **没有** |

### 推断

OriginOS 可能维护着自己的一份闹钟白名单，只有用户在系统页面
**手动打开**那个开关时，才会把应用登记进去。

`USE_EXACT_ALARM` 只让 AOSP 层的 `canScheduleExactAlarms()` 返回 true ——
**系统查询说"可以"，但厂商自己的投递通道里没有这个应用**，于是照样延迟。

这能解释全部现象：权限显示已授权、白名单已加入、闹钟类型最强，却依然晚 3 分钟。

### 改法

**去掉 `USE_EXACT_ALARM`，改回 `SCHEDULE_EXACT_ALARM` + 主动引导用户去开启** ——
与那个在同一台手机上验证可用的应用保持一致。

自检页「精确闹钟」那一项现在会：

- 未开启时显示 ⚠️ 和 **「去开启」** 按钮，点进去就是系统的
  **「闹钟与提醒 → 允许设置闹钟和提醒」** 页面
- 已开启后按钮变成 **「去核对」**，方便随时确认

## ⚠️ 升级说明（这一步必须做）

直接覆盖安装，数据不会丢。

**升级后请务必做这一步**，否则提醒会退化成非精确闹钟、比以前更不准：

1. 打开客脉图 → 进 **设置 → 提醒 → 通知自检与修复**
2. 找到 **「精确闹钟」**，点右边的 **「去开启」**
3. 在系统的 **「闹钟与提醒」** 页面里，把客脉图的开关**打开**
4. 回到应用，那一项应该变成 ✓
5. 点「1 分钟后发一条通知」→ **按 HOME 切后台** → 等一分钟
