## 1. 项目概述

### 1.1 一句话定位

**一款运行在安卓手机上的「客户关系思维导图」**：把每一位客户当作导图上的一个节点，按"谁介绍了谁"的层级关系自动铺开成一张无限延展的图，随时记录客户办卡时间与使用过的产品。

### 1.2 背景与目标

- 使用范围：**私人及朋友之间自用**，不上架应用商店、不面向公众发布。
- 要解决的问题：客户信息散落在微信备注、备忘录、纸笔里，无法一眼看清"客户从哪来、谁介绍了谁、各自办了什么卡"。
- 达成效果：**打开应用就是一张图**，客户之间的介绍脉络一目了然；新增客户只需两步，记录信息不超过 3 个字段。

### 1.3 典型使用场景

| 场景 | 用户动作 |
| --- | --- |
| 老客户 A 介绍来新客户 B、C | 在 A 节点下添加两个"下级"节点 |
| B 又介绍来 D | 在 B 节点下添加下级节点 D |
| 客户办了卡 | 点开该节点 → 选首次办卡日期 → 勾选产品 |
| 回顾某个客户 | 顺着导图找，或用搜索直接定位（见第 8 章 Q3） |
| 换手机 / 重装 | 导出备份文件 → 新机导入恢复 |

### 1.4 本期范围（v1.0）

**✅ 本期实现**

1. 打开即进入**无限画布**，客户以思维导图形式自动排布，横向竖向均可无限延展。
2. 客户节点的新增、编辑、删除；上下级（介绍关系）与同级（并列关系）的建立。
3. 三个内置字段：**客户名称、首次办卡时间、使用过的产品**。
4. **产品库**管理：可新增、重命名、排序、停用产品；录入时多选 + 自动补全。
5. **设置**（右上角齿轮图标）：主题（跟随系统 / 浅色 / 深色）、字号档位（小 / 标准 / 大 / 特大）、产品库管理、数据备份与恢复、关于（底部显示版本号）。
6. **本地数据持久化**：编辑即时自动保存，无需手动保存。
7. **备份导出 / 导入恢复**（JSON 文件）。
8. 完整的浅色 / 深色两套配色。

**❌ 本期明确不做**

| 不做的事 | 原因 / 去向 |
| --- | --- |
| 上架应用商店、公开发布 | 你的明确要求 |
| 账号、登录、云同步、多设备同步 | 私人使用；且应用不联网，隐私最安全 |
| 应用锁（密码 / 指纹） | 你选择"不需要，优先顺手" |
| 回访提醒、待办、通知 | 你说"暂时还没想好"，v1 只做记录与展示 |
| 自定义字段的**管理界面** | 数据模型已预留（见 4.4），功能顺延至 v1.1 |
| 统计报表、图表、客户画像分析 | 顺延至 v2 |
| 图片、附件、语音备注 | 顺延至 v2 |
| 客户搜索 | **待你拍板**，见第 8 章 Q3（我建议 v1 就做） |

## 4. 核心数据结构

### 4.1 核心对象

```
客户 Customer ──(介绍关系)──> 客户 Customer      ← 构成导图的树形结构
      │
      └──(多选)──> 产品 Product                  ← 来自可维护的产品库

设置 Settings                                     ← 主题、字号
```

### 4.2 客户字段（v1 内置，共 3 个）

| 字段 | 类型 | 必填 | 输入方式 | 说明 |
| --- | --- | --- | --- | --- |
| **客户名称** | 单行文本 | ✅ 是 | 键盘输入 | 导图节点上显示的文字，最长 20 字，超出省略 |
| **首次办卡时间** | 日期 | ⬜ 否 | 日期选择器 | 精确到「日」；未填写时节点上有视觉标记 |
| **使用过的产品** | 多选标签 | ⬜ 否 | 从产品库多选 | 可多选；支持边输边搜、搜不到即新建 |
| *（介绍人）* | 引用其他客户 | ⬜ 否 | 选择器 | **不是普通字段**，它决定节点在导图中的位置，见 4.3 |

> 说明：你选择了"最简"方案 —— 只记**首次**办卡时间，不记录多次办卡明细。这意味着同一个客户第二次、第三次办卡不会单独留痕，只体现为"产品"标签的累加。**如果日后发现不够用，扩展成"多次办卡明细"是可行的，但会改动数据结构，建议现在就确认一次**（见第 8 章 Q2）。

### 4.3 关系规则（导图的骨架）

| 规则 | 内容 |
| --- | --- |
| 介绍人数量 | 一个客户**最多只有一个**介绍人（上级） |
| 下级数量 | 一个客户可以有**任意多个**下级 |
| 根节点 | 没有介绍人的客户即为"根客户"，**允许存在多个根** |
| 同级 | 拥有**同一个介绍人**的客户互为同级 |
| 禁止成环 | 不允许 A 介绍 B、B 又（间接）介绍回 A，系统实时校验并拦截 |
| 深度与广度 | 层级深度、同级数量**均不设上限**，可无限延展 |

### 4.4 数据模型（技术预览，便于你确认扩展性）

```jsonc
{
  "schemaVersion": 1,                 // 预留：日后加"自定义字段"时升级此版本号
  "exportedAt": "2026-09-29T10:00:00+08:00",
  "settings": { "theme": "system", "fontScale": "standard" },
  "products": [
    { "id": "p1", "name": "示例产品A", "order": 0, "archived": false }
  ],
  "customers": [
    {
      "id": "c1",
      "name": "客户A",
      "firstCardDate": "2025-03-12",   // 可空
      "productIds": ["p1"],            // 可空数组
      "referrerId": null,              // null = 根客户
      "createdAt": "...", "updatedAt": "..."
    }
  ]
}
```

> **关于自定义字段**：数据采用固定字段 + 预留扩展位的方式。日后要加"自定义字段"时，只需新增 `fieldDefinitions`（字段定义）与 `customValues`（字段值）两组数据，**不会破坏已有数据，也不需要重装应用**。v1.0 先不做管理界面。

> **关于节点坐标**：导图位置由结构**自动计算**，不存储坐标。好处是图永远工整、不会因为误拖而变乱；代价是不能自由摆放（见第 8 章 Q1）。

## 5. 核心界面设计

### 5.1 主界面：无限导图画布

#### 5.1.1 布局规则（★ 最关键，请重点确认）

根据你的描述 ——「A 的下级直接是 B 和 C，B 的下级是 D，B 与 C 同级，不断延伸」，我理解为下面这种**自上而下的树**：

```
                     ┌─────────┐
                     │  客户A  │          ← 根客户（无介绍人）
                     └────┬────┘
              ┌───────────┴───────────┐
              │                       │
         ┌────┴────┐             ┌────┴────┐
         │  客户B  │             │  客户C  │   ← B、C 同级（横向并排）
         └────┬────┘             └─────────┘
              │
         ┌────┴────┐
         │  客户D  │                        ← B 的下级
         └─────────┘
```

| 方向 | 含义 | 效果 |
| --- | --- | --- |
| **竖向（向下）** | 层级变深 | 下级永远排在上级**下方**，形成代际 |
| **横向（左右）** | 同级并列 | 兄弟节点从左到右依次排开，互不遮挡 |
| 自动对齐 | — | 父节点**水平居中**于其所有子节点之上 |
| 无限延展 | — | 深度和宽度都不设上限，画布随之无限扩展 |

> ⚠️ **这里需要你确认**：草图里「客户A」在左下角、连线往右上发散，观感更像"上级在左、下级在右"。而你的文字描述是"竖向 = 下级、横向 = 同级"。我按**文字描述**做成了上面的自上而下结构。若你想要的是自左向右，请见第 8 章 **Q1**，那里有两种方向的对照图。

#### 5.1.2 多个根客户怎么排

允许存在多个互不相关的根客户，它们**从左到右横向并排**，各自带自己的一整棵子树，子树之间留出更大间距以示分隔：

```
   ┌─────────┐        ┌─────────┐        ┌─────────┐
   │  客户A  │        │  客户X  │        │  客户M  │
   └────┬────┘        └────┬────┘        └─────────┘
   ┌────┴────┐             │
┌──┴──┐   ┌──┴──┐     ┌────┴────┐
│客户B│   │客户C│     │  客户Y  │
└─────┘   └─────┘     └─────────┘
```

#### 5.1.3 画布操作

| 手势 / 操作 | 行为 |
| --- | --- |
| 单指拖动**空白处** | 平移画布（无限平移） |
| 双指捏合 | 缩放画布，范围 30% ~ 250%，超出范围有回弹 |
| 双指拖动 | 平移画布 |
| **单击**客户节点 | 选中，节点高亮，底部浮现操作条 |
| **双击**客户节点 | 直接打开编辑面板 |
| **长按**客户节点 | 弹出快捷菜单（加下级 / 加同级 / 编辑 / 改介绍人 / 删除） |
| 单击空白处 | 取消选中 |
| 右下角「适应全图」按钮 | 一键缩放到能看到全部客户 |
| 右下角「＋」按钮 | 新建一个根客户 |

### 5.2 客户节点卡片

| 项目 | 设计 |
| --- | --- |
| 显示内容 | **仅显示客户名称**（你选择的"最整洁"方案） |
| 卡片尺寸 | 高度固定 44dp；宽度随名称自适应，最小 88dp、最大 200dp，超出省略号 |
| 形状 | 圆角矩形（12dp 圆角），轻微投影 |
| 颜色 | 按"根客户"分配色系：同一棵子树使用同一色相，根节点色最深，往下逐层变浅 |
| 左侧色条 | 卡片左侧 3dp 竖色条，标识所属子树 |
| 状态标记 | 已填办卡时间 → 卡片右上角一个小圆点；未填 → 无标记 |
| 选中态 | 描边加粗 + 投影增强 + 轻微放大（1.03 倍） |
| 根节点 | 卡片左上角多一条短横线装饰，区别于下级 |
| 下级数量 | 若该客户有下级，卡片下方显示 `n 位下级` 小字（可关，见 Q7） |

### 5.3 连线

| 项目 | 设计 |
| --- | --- |
| 样式 | **圆角折线**（从父节点底部垂直下行 → 水平横向 → 垂直下行到子节点），转角 8dp 圆角，比曲线更"工整" |
| 颜色 | 继承所属根客户的色相，比节点色浅一档 |
| 粗细 | 固定 1.5dp；选中链路时加粗至 2.5dp 并高亮 |
| 多子节点 | 从父节点底部引出一条主干，再分叉到各子节点（见上方示意图） |

- **保存**：保存后导图自动重新排布，新节点以动画"生长"出来，并自动平移到视口内。

## 6. 交互流程（关键路径）

### 6.1 创建第一位客户
点击空状态按钮 → 编辑面板 → 填名称 → 保存 → 画布出现第一个节点并居中。

### 6.2 添加下级（老带新）
选中客户A → 「＋ 加下级」→ 编辑面板（介绍人已自动填为客户A）→ 填名称 → 保存 → 客户A 下方长出子节点，A 自动水平居中。

### 6.3 添加同级
选中客户B（其介绍人为A）→ 「＋ 加同级」→ 保存 → 新节点排在 B 右侧，同为 A 的下级。

### 6.4 修改介绍人（纠正错误）
选中客户 → 编辑 → 改「介绍人」→ 保存 → 该客户连同其**整棵子树**一起迁移到新位置，有平移动画。

### 6.5 删除客户（⚠️ 有下级时的处理）

删除一个**带有下级**的客户时，必须让用户明确选择，不允许静默处理：

```
┌────────────────────────────────────────────┐
│  删除「客户A」？                           │
│                                            │
│  该客户名下还有 2 位下级客户。             │
│                                            │
│  ○ 下级上提（推荐）                        │
│    客户B、客户C 变成根客户，数据保留       │
│                                            │
│  ○ 连同下级一起删除                        │
│    将一并删除 3 位客户，不可恢复           │
│                                            │
│           [ 取消 ]      [ 确认删除 ]       │
└────────────────────────────────────────────┘
```

- 无下级的客户：仅需一次普通确认。
- 所有删除操作均可通过"导入上一次备份"找回。

### 6.6 导出备份 / 导入恢复

| 操作 | 流程 |
| --- | --- |
| **导出备份** | 设置 → 导出备份 → 系统文件选择器 → 保存为 `客脉图备份_20260929_1030.json` |
| **导入恢复** | 设置 → 导入恢复 → 选择文件 → **自动先把当前数据另存一份回滚备份** → 提示"将覆盖当前 N 位客户数据" → 确认后导入 → 画布刷新 |
| 异常处理 | 文件损坏 / 格式不符时明确提示，**不破坏现有数据** |

## 7. 视觉与设计规范

### 7.1 设计原则

**工整、克制、耐看**。无限画布最怕杂乱，因此：靠色相区分家族的树、靠圆角折线保证连线利落、靠留白和统一的间距网格保证呼吸感。

### 7.2 配色

**主色：青瓷蓝绿**（沉稳、清爽，与"脉"的意象契合）

| 主色 | `#2F6E6A` | `#7FC9C2` |
| 画布背景 | `#FBFAF7`（暖白） | `#14181A` |
| 网格点 | `#00000014` | `#FFFFFF12` |
| 卡片底色 | `#FFFFFF` | `#1E2426` |
| 主文字 | `#1C2321` | `#E8EDEB` |
| 次文字 | `#6B7674` | `#93A09D` |
| 分隔线 | `#E6E4DF` | `#2C3436` |

**子树色相轮换**（同一棵子树同一色相，根最深、逐层变浅）

| # | 色相 | 浅色模式基色 | 深色模式基色 |

### 7.3 字号档位

### Q1. 导图方向（最关键）

你说的"竖向 = 下级、横向 = 同级"，我按 **A 方案** 实现了。请确认：

### Q2. 布局方式：自动排布 vs 手动拖动

- **C 完全自由摆放**：像白板一样随便放，只靠连线表示关系（最灵活，但与"工整"目标冲突）。

> 👉 选哪个？（我推荐 A，这样"竖向 = 下级、横向 = 同级"的语义才是严格的。）
