# 发布流程

> 以后每出一个新版本，照这个流程走一遍就行。

---

## 仓库结构

本工作区里其实有**两个** git 仓库：

| 位置 | 用途 | 公开性 |
| --- | --- | --- |
| 工作区根目录 `Application_development_1\` | **发布仓库**：使用说明、版本历史、界面截图、安装包 | 公开 |
| `KemaiTu\` | **源码仓库**：完整 Android 工程 | 暂不公开（将来想开源再推） |

根目录的 `.gitignore` 里已经把 `KemaiTu/`、`工具/`、`docs/客脉图_需求文档_*.md`、
`.android/` 都排除掉了 —— 这些**不会**被推到公开仓库。

想确认到底会推上去哪些文件：

```powershell
git ls-files
```

当前应该正好是 14 个文件。

## 发一个新版本

### 1. 改版本号

`KemaiTu\app\build.gradle.kts`：

```kotlin
versionCode = 7          // 每次 +1，不能重复
versionName = "1.4.1"    // 对外显示的版本号
```

### 2. 构建并安装包

```powershell
powershell -ExecutionPolicy Bypass -File 工具\2-构建并安装.bat
```

然后把产物复制到 `releases\`：

```powershell
copy KemaiTu\app\build\outputs\apk\debug\app-debug.apk releases\客脉图_v1.4.1_debug.apk
```

### 3. 采集新截图（界面有变化时）

用模拟器跑一遍，把 `工具\shots\` 里的图替换到 `docs\screenshots\`。

命名规则：`NN-功能名.png`，按顺序编号。

### 4. 写版本说明

- 在 `CHANGELOG.md` 顶部加一节 `## [v1.4.1] — 一句话标题`
- 新建 `docs\RELEASE_v1.4.1.md`（内容就是 GitHub Release 的正文）
  - 可以直接复制上一版的 `RELEASE_*.md` 改

### 5. 提交并打标签

```powershell
git add -A
git commit -m "客脉图 v1.4.1：一句话说明"
git tag -a v1.4.1 -m "客脉图 v1.4.1"
```

> 源码也要提交的话，进 `KemaiTu\` 目录重复一遍 add / commit / tag。

### 6. 推送

```powershell
powershell -ExecutionPolicy Bypass -File 工具\3-推送到GitHub.ps1
```

脚本会把分支和 tag 推上去，然后打印创建 Release 的步骤。

### 7. 在网页上发 Release

打开 `https://github.com/lyq-05/kemai-tu/releases/new`：

| 字段 | 填什么 |
| --- | --- |
| Choose a tag | 选刚推上去的 `v1.4.1` |
| Release title | `客脉图 v1.4.1` |
| 说明 | 把 `docs\RELEASE_v1.4.1.md` 的内容整个粘进去 |
| 附件 | 把 `releases\客脉图_v1.4.1_debug.apk` 拖进去 |
| | 点 **Publish release** |

发完之后，`README.md` 里那个 `../../releases` 链接会自动指向最新版。

## 第一次推送前要做的事

GitHub 上**先建一个空仓库**：

1. 打开 https://github.com/new
2. Repository name 填 `kemai-tu`
3. 选 **Public**（要让别人能下载安装包就必须是 Public）
4. **不要**勾选 Add a README file / Add .gitignore / Choose a license
5. 点 Create repository

然后再运行推送脚本。

## 常见问题

**Q：推送时提示要登录？**

系统里已经存过 github.com 的凭据了，正常不会再问。
如果真被问到，用户名填 `lyq-05`，密码那里填 **Personal Access Token**（不是账号密码）。
去 https://github.com/settings/tokens 生成一个，勾 `repo` 权限就够。

**Q：怎么确认源码没被推上去？**

```powershell
git ls-files | Select-String "KemaiTu"
```

没有任何输出就对了。

**Q：以后想开源怎么办？**

在 `KemaiTu\` 里建个远程仓库推上去就行，两个仓库互不影响：

```powershell
cd KemaiTu
git remote add origin https://github.com/lyq-05/kemai-tu-src.git
git push -u origin main
git push origin --tags
```
