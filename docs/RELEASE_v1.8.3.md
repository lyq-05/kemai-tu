## 🚀 本次更新

### 新增：「系统怎么看待本应用」诊断行

Android 会按使用频率把每个应用丢进不同的**「应用待机桶」**，
桶越"冷"，它的闹钟和后台任务被延迟得越狠：

| 档位 | 含义 |
| --- | --- |
| 活跃 / 常用 / 较常用 | 系统不会刻意延迟 |
| **很少使用** | 闹钟会被延迟 |
| **受限制** | 闹钟会被严重延迟 |

自检页现在会显示客脉图当前在哪个档，并给出判断。

**这一项不需要任何权限**就能读（读自己应用的档位是允许的），
所以它是一条**全自动、可验证**的证据 —— 如果它显示"很少使用"或"受限制"，
那就说明问题出在系统怎么看待这个应用，而不是闹钟本身。

## 🔍 排查进展：应用侧已经做到头了

用户实测数据（iQOO Neo9S Pro+ / OriginOS 4 / Android 14）：

```
本次排定    10月5日 09:00 · 闹钟式（最可靠，不怕省电策略）   ← 最强闹钟类型
系统电池优化 ✓ 已加入白名单                                ← Doze 白名单已进
精确闹钟     ✓ 已授权                                      ← 权限已拿到
上一次闹钟   预定 10月1日 00:18 → 实际 10月1日 00:22（晚 3 分钟）
```

**应用侧能做的三件事全部就位，系统仍然延迟 3 分钟。**

这排除了应用代码的问题，把范围收窄到**厂商自己的后台管理**：

| 层面 | 谁负责 | 应用能不能自动搞定 |
| --- | --- | --- |
| 闹钟类型、精确闹钟权限、Doze 白名单、通知渠道 | 应用 | ✅ 已全部做到 |
| **自启动、后台耗电管理、后台冻结** | **厂商 ROM** | ❌ **Android 没有给应用任何 API，只能由用户手动设** |

所以下一步不是改代码，而是**把厂商那层的设置补齐**。
自检页的「厂商后台策略 → 查看步骤」里有按品牌列的具体路径。
